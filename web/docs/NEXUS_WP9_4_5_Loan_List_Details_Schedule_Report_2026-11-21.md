# WP9.4.5 — Loan List, Details and Repayment Schedule

Date: 2026-11-21

## Scope completed

Replaced the borrower loans placeholder with a paginated loan list and individual loan detail/schedule pages. Read APIs now include persisted schedule summaries and installment amounts so the frontend renders backend data without calculating loan balances or schedules.

## API and data behavior

- `GET /api/borrower/loans` retains borrower ownership, pagination, and supported created-date sorting. For loans with a current schedule it returns original principal, outstanding principal, outstanding balance, and installment count derived from persisted installments. Loans without a schedule return `null` outstanding values and a zero installment count.
- `GET /api/borrower/loans/{loanId}` remains borrower-scoped and now returns original principal, principal/interest paid, total paid, principal/interest outstanding, total outstanding, installment count, maturity date, and schedule version reference when a schedule exists.
- `GET /api/borrower/loans/{loanId}/schedule` remains read-only and borrower-scoped. Each row now includes total due, paid amount, remaining amount, last posted repayment timestamp, and the backend installment status alongside persisted principal, interest, opening principal, and due date.
- The schema stores a single `dueDate` for schedule timing. The API exposes that value as both `dueDate` and `scheduledPaymentDate`; the UI labels it “Due / scheduled date” to make this shared source explicit. Actual payment timing is shown separately as “Last payment.”
- Balance arithmetic is performed at the API boundary over persisted satang values using integer `BigInt` arithmetic. React does not recalculate scheduled interest, principal, totals, or statuses.

## Frontend

- `/borrower/loans` now shows responsive loan cards with reference, principal, outstanding principal, rate, term, disbursement date, and backend status, plus loading/error/empty/pagination states.
- `/borrower/loans/{loanId}` shows loan details and the current repayment schedule.
- Schedule table displays installment sequence, due/scheduled date, opening principal, interest, principal, total due, paid, remaining, latest payment date, and the exact backend status. It scrolls horizontally on narrow screens.
- Schedule loading and errors are handled separately from loan detail loading/errors. Loans without a disbursement date explain that the schedule becomes available after disbursement.
- Dashboard loan rows now link directly to the loan detail page.

## Decisions and boundaries

- No loan or schedule values are shown as placeholders that resemble financial data. If no schedule exists, balance fields remain unavailable and the UI indicates schedule pending.
- The frontend uses status values from the existing loan and installment enums and does not infer overdue status from dates.
- No repayment schedule is generated by these reads or by the UI.
